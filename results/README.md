# Result files and where the paper uses them

All numbers in the paper are generated from these files by `paper/make_numbers.py`.

| File | Paper |
|---|---|
| `v2/c3_audit_n3000_m100.csv` | Sect. 6, admissibility audit (main run, Fig. 2) |
| `c3_audit_n3000_m200.csv`, `c3_audit_n3000_m100_seed1.csv` | Sect. 6, robustness (m = 200, second seed) |
| `t7_counterexample.json` | Sect. 3, counterexample (Fig. 1) and random search |
| `t8_twin.jsonl` | Sect. 5, float32 error of the GPU code (CPU twin) |
| `t5_twin.jsonl` | Sect. 5, twin vs Python reference validation |
| `wide/wide_audit_n3000_m100.csv` | Sect. 7, wider audit and history-based limits (Table 1) |
| `wide/wide_audit_n3000_m50.csv`, `_m200.csv`, `_m100_seg40000.csv`, `_m100_seed1.csv` | Sect. 7, robustness of the wider audit (m = 50 and 200, second segment, second seed) |
| `c2/c2_cwru.csv`, `c2/c2_planted.csv` | Sect. 8, comparison with exclusion and imputation |
| `c2/c2_saits_cwru.csv`, `c2/c2_saits_planted.csv` | Sect. 8, the learned-imputer (SAITS) rows of the same comparison |
| `pamap2/pamap2_case.csv` | Sect. 7, real-saturation case study (PAMAP2, 15 segments, 5 subjects) |
| `gpu/` (after the Kaggle runs) | Sect. 5, GPU agreement, sanitizer and speed |

Each result CSV is accompanied by the run's `.log` (console output) and `.meta.json` (the exact
argv, the parameters, the datasets and the runtime), so every row can be traced to the run that
produced it. `c2/c2_summary.json` is the exception: it is not an input but the per-method summary
that `paper/make_numbers.py` writes out of the two `c2` CSVs, committed so the aggregates can be
read without re-running it. `t8_numerics*` is an earlier NumPy float32 emulation, kept for reference; the paper
uses the twin. `*_tables*.md` are human-readable summaries of the matching CSVs, regenerated by
`audit/summarize.py`.

In `gpu/`, the paper quotes `agree_after_refactor.jsonl` for GPU-vs-twin agreement: it is the
re-run made after the kernels moved out of `mdms_gpu.cu` into `mdms_kernels.cuh`, so it describes
the code as it ships. `agree_smoke.jsonl` is the same 12 cases on the pre-refactor code, kept so
the claim can be checked against either. Both are 12/12 bitwise-equal with identical indices.
